## 1. Как работает программа traceroute

**Traceroute** — утилита для определения маршрута пакетов до целевого хоста.

### Принцип работы:
1. **TTL (Time To Live)** — поле в IP заголовке, ограничивающее время жизни пакета. Каждый маршрутизатор (hop) уменьшает TTL на 1. Когда TTL становится 0, пакет уничтожается, и маршрутизатор отправляет обратно ICMP **Time Exceeded** (type=11, code=0).

2. **Алгоритм**:
   - Отправляем пакет с TTL=1 → первый роутер возвращает Time Exceeded → узнаём IP первого хопа
   - Отправляем пакет с TTL=2 → второй роутер возвращает Time Exceeded → узнаём IP второго хопа
   - Продолжаем увеличивать TTL до достижения цели или max_hops
   - Когда пакет достигает целевого хоста, он отвечает **ICMP Echo Reply** (type=0) — трассировка завершена

3. **Измерение RTT**: В payload ICMP пакета кладём timestamp отправки. При получении ответа (Time Exceeded или Echo Reply) вычисляем разницу: RTT = time_now - timestamp_sent.

4. **Три пробы на хоп**: Обычно отправляют 3 пакета на каждый TTL для статистики (min/avg/max).

### Реализация в нашем коде:
- `Traceroute` класс в `traceroute.py`
- Использует raw socket с `IP_TTL` опцией
- Отправляет ICMP Echo Request с увеличением TTL
- Обрабатывает Time Exceeded, Echo Reply, Destination Unreachable

## 2. Механизм действия Smurf атаки

### Что такое Smurf атака:
**Smurf** — DoS атака с усилением (amplification attack) на основе ICMP и IP spoofing.

### Механизм:
1. **Подготовка**: Атакующий определяет broadcast адрес целевой сети (например, 192.168.1.255 для сети 192.168.1.0/24) и IP адрес жертвы.

2. **Спуфинг**: Атакующий формирует ICMP Echo Request пакет с **поддельным source IP** (IP жертвы) вместо своего.

3. **Отправка на broadcast**: Пакет отправляется на broadcast адрес сети.

4. **Амплификация**: Все хосты в broadcast домене получают запрос и отвечают ICMP Echo Reply на **IP жертвы** (source IP в пакете).

5. **Результат**: От одного пакета атакующего генерируется N ответов (где N = количество хостов в сети). Жертва получает флуд ICMP ответов.

### Угрозы:
- **DoS/DDoS**: Жертва перегружается входящим трафиком
- **Амплификация**: Коэффициент усиления = количество хостов в broadcast домене (может быть 100x+)
- **Сложность отслеживания**: Реальный IP атакующего скрыт (spoofed)
- **Коллатеральный ущерб**: Все хосты в broadcast домене задействованы как "рефлекторы"

### Способы защиты:
1. **Отключение directed broadcast на роутерах** (Cisco: `no ip directed-broadcast`) — роутер не пересылает broadcast пакеты в локальную сеть
2. **Ingress filtering (BCP 38 / RFC 2827)** — провайдеры блокируют пакеты с source IP, не принадлежащими клиенту
3. **Egress filtering** — блокировка исходящих пакетов с невалидными source IP
4. **Rate limiting ICMP** — ограничение количества ICMP пакетов в секунду
5. **Отключение ICMP Echo Reply на хостах** (не рекомендуется — ломает ping/traceroute)
6. **Настройка файерволов** — блокировка ICMP от неизвестных сетей

## 3. Назначение полей заголовка протокола IP (IPv4)

| Поле | Размер | Назначение |
|------|--------|------------|
| **Version** | 4 бита | Версия протокола (4 для IPv4) |
| **IHL (Internet Header Length)** | 4 бита | Длина заголовка в 32-битных словах (минимум 5 = 20 байт) |
| **DSCP / TOS** | 8 бит | Differentiated Services Code Point / Type of Service — QoS, приоритет |
| **Total Length** | 16 бит | Общая длина пакета (заголовок + данные) в байтах, макс. 65535 |
| **Identification** | 16 бит | Уникальный ID для фрагментации — все фрагменты одного пакета имеют одинаковый ID |
| **Flags** | 3 бита | Контроль фрагментации: Reserved, DF (Don't Fragment), MF (More Fragments) |
| **Fragment Offset** | 13 бит | Смещение фрагмента в оригинальном пакете (в 8-байтовых блоках) |
| **TTL (Time To Live)** | 8 бит | Счётчик хопов. Уменьшается на 1 на каждом роутере. 0 = пакет уничтожается |
| **Protocol** | 8 бит | Протокол следующего заголовка: 1=ICMP, 6=TCP, 17=UDP, и т.д. |
| **Header Checksum** | 16 бит | Контрольная сумма только заголовка (пересчитывается на каждом хопе) |
| **Source IP** | 32 бита | IP адрес отправителя |
| **Destination IP** | 32 бита | IP адрес получателя |
| **Options** | Переменная | Опциональные поля (record route, timestamp, security) — редко используются |

### Особенности:
- **Минимальный заголовок**: 20 байт (IHL=5, без опций)
- **Максимальный заголовок**: 60 байт (IHL=15)
- **Checksum** покрывает только заголовок, не данные — пересчитывается на каждом хопе из-за изменения TTL
- **Фрагментация**: Если пакет больше MTU следующего звена и DF=0, пакет фрагментируется. Сборка только на конечном хосте.

## Дополнительно: Реализация в коде

### Raw Sockets:
- **Linux**: `socket(AF_INET, SOCK_RAW, IPPROTO_ICMP)` — ядро строит IP заголовок
- **Windows**: `socket(AF_INET, SOCK_RAW, IPPROTO_IP)` + `IP_HDRINCL=1` — строим IP заголовок сами

### ICMP Checksum:
```python
def calculate_checksum(data):
    if len(data) % 2: data += b"\x00"
    s = sum(struct.unpack("!%dH" % (len(data)//2), data))
    s = (s >> 16) + (s & 0xFFFF)
    s += s >> 16
    return ~s & 0xFFFF
```

### MSG_PEEK для параллельного ping:
В `ping.py` используется `select.select()` для неблокирующего ожидания ответов. При использовании **общего сокета** для всех потоков (а не по сокету на поток), `MSG_PEEK` позволяет:
1. `recvfrom(..., MSG_PEEK)` — прочитать пакет без удаления из буфера
2. Проверить `id` и `seq` в ICMP payload
3. Если пакет "наш" — `recvfrom` без флага (удалить), иначе — оставить для других потоков

В текущей реализации каждый поток создаёт свой raw socket, что проще и надежнее на Linux, но требует больше файловых дескрипторов.
