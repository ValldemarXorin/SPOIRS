# Лабораторная работа №6 — Ответы на вопросы

## 1. В чем отличие многоадресной и широковещательной передачи?

| Характеристика | Широковещательная (Broadcast) | Многоадресная (Multicast) |
|----------------|-------------------------------|---------------------------|
| **Адресация** | Один адрес для всех хостов в сегменте (например, 192.168.1.255) | Групповой адрес (224.0.0.0 – 239.255.255.255) |
| **Получатели** | Все хосты в L2-сегменте (обязательно обрабатывают) | Только хосты, вступившие в группу (IGMP join) |
| **Маршрутизация** | Не проходит через роутеры (кроме directed broadcast) | Маршрутизируется через сеть (PIM, IGMP snooping) |
| **Эффективность** | Нагружает все хосты сегмента, даже не заинтересованные | Трафик получают только подписчики группы |
| **Протоколы** | ARP, DHCP, NetBIOS | IPTV, видеоконференции, OSPF/RIPv2, mDNS |
| **Управление** | Нет (все получают) | IGMP (Internet Group Management Protocol) для входа/выхода |

**Ключевое отличие**: Broadcast — «один ко всем в сегменте», Multicast — «один к группе заинтересованных получателей в сети».

## 2. Как формируется широковещательный адрес?

Широковещательный адрес IPv4 вычисляется как **побитовое ИЛИ (OR) между IP-адресом хоста и инвертированной сетевой маской**:

```
Broadcast = IP | (~Netmask)
```

**Пример**:
- IP: `192.168.1.10` → `11000000.10101000.00000001.00001010`
- Маска: `255.255.255.0` → `11111111.11111111.11111111.00000000`
- Инверт маски: `00000000.00000000.00000000.11111111` = `0.0.0.255`
- Broadcast: `192.168.1.10 | 0.0.0.255` = `192.168.1.255`

**Специальные случаи**:
- `255.255.255.255` — limited broadcast (только локальный сегмент, не маршрутизируется)
- Directed broadcast — broadcast конкретной подсети (может проходить роутеры если разрешено)

## 3. Какие диапазоны адресов многоадресной передачи существуют? Каково их назначение?

| Диапазон | Название | Область | Назначение |
|----------|----------|---------|------------|
| **224.0.0.0 – 224.0.0.255** (224.0.0.0/24) | Link-Local | Только локальный сегмент (TTL=1) | Протоколы маршрутизации: OSPF (224.0.0.5/6), RIPv2 (224.0.0.9), VRRP (224.0.0.18), PIM (224.0.0.13) |
| **224.0.1.0 – 224.0.1.255** (224.0.1.0/24) | Internetwork | Маршрутизируется в интернете | NTP (224.0.1.1), AUTO-RP (224.0.1.39/40), Musicam (224.0.1.11) |
| **224.0.2.0 – 224.0.255.255** | Адреса приложений | Глобальная маршрутизация | Различные приложения (назначаются IANA) |
| **232.0.0.0 – 232.255.255.255** (232.0.0.0/8) | **SSM** (Source-Specific Multicast) | Только (S,G) подписка | IPTV, потоковое видео — получатель указывает источник |
| **233.0.0.0 – 233.255.255.255** | GLOP | На основе AS номеров | Для организаций с AS номером (233.[AS_high].[AS_low].0/24) |
| **239.0.0.0 – 239.255.255.255** (239.0.0.0/8) | **Admin Scope** (административная область) | Ограничивается администратором | Локальные приложения, корпоративные чаты, видео — не выходит за границы организации |

**В нашем чате используется**: `239.255.0.1` (из Admin Scope) — гарантированно локальный, не конфликтует с интернетом.

## 4. Какие есть механизмы ограничения области распространения многоадресных пакетов?

1. **TTL (Time To Live) / IP_MULTICAST_TTL**
   - Значение TTL в IP-заголовке ограничивает количество хопов
   - TTL=1 — только локальный сегмент (link-local)
   - TTL=16 — в пределах организации
   - TTL=127 — глобально

2. **Administrative Scoping (Admin Scope)**
   - Диапазон `239.0.0.0/8` зарезервирован для локального использования
   - Роутеры на границе организации блокируют эти адреса
   - Можно выделять поддиапазоны: site-local, organization-local

3. **Multicast Routing Protocols (PIM, DVMRP)**
   - PIM-SM (Sparse Mode) — дерево с rendezvous point, трафик идет только туда, где есть подписчики
   - PIM-DM (Dense Mode) — flood & prune
   - IGMP Snooping на L2-коммутаторах — не флудит multicast на порты без подписчиков

4. **IGMP (Internet Group Management Protocol)**
   - IGMP v1/v2/v3 — хосты сообщают роутерам о вступлении/выходе из групп
   - IGMP v3 — Source-Specific Multicast (SSM): подписка на (S,G) вместо просто G

5. **Scope Boundaries на роутерах**
   - Администратор настраивает границы зон (boundaries) на интерфейсах роутеров
   - ACL для multicast: `ip multicast boundary` (Cisco)

6. **VLAN / L2 Segmentation**
   - Multicast не выходит за VLAN без L3 маршрутизации

## 5. Какова область распространения широковещательных пакетов?

1. **Limited Broadcast (255.255.255.255)**
   - Только в пределах **одного L2-сегмента** (broadcast domain)
   - Не проходит через роутеры (TTL не применяется, роутеры не форвардят)
   - Используется: DHCP Discover, ARP (в некоторых случаях)

2. **Directed Broadcast (Network Broadcast, e.g., 192.168.1.255)**
   - В пределах **одной IP-подсети** (L2-сегмент)
   - Может быть передан роутерами **если явно разрешено** (команда `ip directed-broadcast` на Cisco)
   - По умолчанию современные роутеры блокируют directed broadcast (защита от Smurf-атак)

3. **Подсетевой broadcast (Subnet Broadcast)**
   - Для неклассовых масок: последние адреса подсети
   - Тоже не проходит роутеры без явного разрешения

**Итог**: Широковещательные пакеты **не выходят за границы broadcast domain (L2-сегмента)** без специальной настройки роутеров. Это фундаментальное отличие от multicast, который маршрутизируется по сети.

## Дополнительно: Реализация в чате

В нашем P2P чате:
- **Один приёмный сокет**: `SO_BROADCAST=1` не нужен для приёма, сокет привязан к `("", порт)` и вступает в multicast группу — принимает и broadcast, и multicast
- **Отдельный send-сокет**: `SO_BROADCAST=1`, `IP_MULTICAST_TTL=2`; отправка на `<broadcast_ip>:порт` или на группу `239.255.0.1` (Admin Scope) — не выходит за роутер
- **Broadcast для хотспотов**: сеть `172.20.10.x` (iPhone) имеет маску /28, поэтому broadcast считается как `172.20.10.15`
- **Discovery**: PING-маяки каждые 2.5 сек в текущем режиме, TTL пира 10 сек
- **Ignore**: работает локально (чёрный список по IP)
