# Lab 6: P2P Chat (Broadcast + Multicast)

Одноранговый чат на UDP с поддержкой широковещательной и многоадресной передачи.
Логика из эталонного `lr6.py`.

## Возможности
- **Broadcast режим** — обнаружение участников в локальном сегменте (L2)
- **Multicast режим** — доставка сообщений группе (группа 239.255.0.1, Admin Scope), join/leave
- **Автоопределение сети** — IP через маршрут по умолчанию, маска и broadcast
- **Поддержка хотспотов телефона** — для сети `172.20.10.x` (iPhone, маска /28) broadcast считается корректно (`172.20.10.15`)
- **Peer Discovery** — PING-маяки каждые 2.5с, удаление пиров через 10с без PING
- **Ignore список** — локальный чёрный список по IP

## Запуск

```bash
# Базовый запуск (спросит никнейм)
python -m lab6

# С указанием имени
python -m lab6 -n "Alice"

# С указанием порта и multicast группы
python -m lab6 -p 50050 -g 239.255.0.1

# Справка
python -m lab6 --help
```

По умолчанию используется порт `50050` и группа `239.255.0.1`.

## Команды чата

| Команда | Описание |
|---------|----------|
| `/mode b` | Переключить режим отправки на BROADCAST |
| `/mode m` | Переключить режим отправки на MULTICAST |
| `/peers` | Список активных участников |
| `/ignore <ip>` | Добавить хост в чёрный список |
| `/unignore <ip>` | Убрать хост из чёрного списка |
| `/join` | Войти в multicast группу |
| `/leave` | Выйти из multicast группы |
| `/exit` | Выйти из чата |

Обычный текст отправляется как сообщение в чат.

## Логика работы (как в эталонном lr6.py)

- **Локальный IP** определяется через `connect(("8.8.8.8", 80))` — берётся интерфейс маршрута по умолчанию.
- **Broadcast** считается по маске; для хотспотов `172.20.10.x` используется маска `/28`, поэтому broadcast = `172.20.10.15` (иначе через хотспот телефона пакеты уходят не туда).
- **Один recv-сокет** привязан к `("", port)` (`SO_REUSEADDR` + `SO_REUSEPORT` на Linux) и вступает в multicast группу — принимает и broadcast, и multicast датаграммы.
- **Отдельный send-сокет** с `SO_BROADCAST` и `IP_MULTICAST_TTL=2` шлёт в текущем режиме.
- **Discovery**: каждый участник каждые 2.5с шлёт `PING`; пир считается активным 10с без PING.
- **Формат сообщений**:
  ```json
  {"type": "PING|TEXT", "sender": "Alice", "ip": "192.168.1.5", "content": "Hello!"}
  ```

```
┌─────────────────────────────────────────────────┐
│                   P2PChat                       │
├─────────────┬───────────────────┬───────────────┤

└─────────────┴───────────────────┴───────────────┘
```

### Сетевой слой (`network.py`)
- `get_local_interfaces()` — IP/маска/broadcast (спец-случай хотспота `172.20.10.x`)
- `create_recv_socket()` / `create_send_socket()` — один приёмный и один передающий сокет
- `join_multicast()` / `leave_multicast()` — вход/выход из группы

### Чат (`chat.py`)
- `P2PChat` — `setup_sockets()`, `send_packet()` (JSON PING/TEXT), `heartbeat_loop()` (2.5с),
  `receive_loop()`, `display_peers()`, `cleanup()`

### CLI (`cli.py`)
- `ChatCLI` — команды `/mode b|m`, `/peers`, `/ignore`, `/unignore`, `/join`, `/leave`, `/exit`
- `main()` — argparse: `-p/--port`, `-g/--group`, `-n/--name`

## Требования

- Python 3.8+

Работает на Windows и Linux без дополнительных зависимостей.

## Тестирование

Запустите два экземпляра на разных машинах в одной сети (или в двух терминалах одной машины):

```bash
# Терминал 1
python -m lab6 -n "Alice"

# Терминал 2
python -m lab6 -n "Bob"
```

Оба увидят друг друга через PING-маяки (~2.5с). Попробуйте:
- Написать сообщения — отображаются как `[Name @ IP]: текст`
- `/peers` — список участников
- `/mode m` — переключиться на multicast, `/join` / `/leave`
- `/ignore <ip>` — добавить хост в чёрный список
- `/exit` — выход

**Если работает через роутер, но не через хотспот телефона:** на Windows проверьте, что сеть определена как «Частная», и добавьте правило файрвола для входящего UDP на порт 50050:

```powershell
netsh advfirewall firewall add rule name="P2P Chat UDP 50050" dir=in action=allow protocol=UDP localport=50050
```

Также в настройках хотспота телефона отключите «изоляцию клиентов» (AP isolation), если она есть.
