# Лабораторная работа №7 — Ответы на вопросы

## 1. Что такое MPI_COMM_WORLD?

**MPI_COMM_WORLD** — это предопределённый (predefined) коммуникатор в MPI, который создаётся автоматически при инициализации MPI (`MPI_Init`). Он включает **все процессы**, запущенные в рамках данного MPI-приложения.

### Основные свойства:
- **Универсальность**: Доступен сразу после `MPI_Init` без дополнительного создания
- **Группа процессов**: Содержит все процессы приложения (world group)
- **Ранги**: Каждому процессу присваивается уникальный ранг от `0` до `size-1`
- **Размер**: `MPI_Comm_size(MPI_COMM_WORLD, &size)` возвращает общее число процессов
- **Ранг текущего процесса**: `MPI_Comm_rank(MPI_COMM_WORLD, &rank)`

### Аналогия:
MPI_COMM_WORLD — это «глобальная комната», где находятся все процессы. Любой процесс может отправить сообщение любому другому, зная его ранг.

### Создание подкоммуникаторов:
Из MPI_COMM_WORLD можно создавать новые коммуникаторы (`MPI_Comm_split`, `MPI_Comm_create`, `MPI_Comm_create_group`) для организации процессов в группы (как в ЛР8).

## 2. Что такое rank?

**Rank (ранг)** — это уникальный целочисленный идентификатор процесса внутри коммуникатора.

### Особенности:
- **Диапазон**: от `0` до `comm_size - 1`
- **Уникальность**: В пределах одного коммуникатора никакие два процесса не имеют одинаковый ранг
- **Порядок**: Ранги идут последовательно: 0, 1, 2, ..., size-1
- **Локальность**: Ранг имеет смысл только внутри конкретного коммуникатора. Один и тот же процесс может иметь разные ранги в разных коммуникаторах.

### Использование:
- Адресация в точечных операциях: `MPI_Send(buf, ..., dest_rank, ...)` / `MPI_Recv(buf, ..., source_rank, ...)`
- Распределение работы: `if (rank == 0) { master_work(); } else { worker_work(); }`
- Определение порции данных: `local_n = n / size; start = rank * local_n;`

### Пример:
```
MPI_COMM_WORLD (size=4)
┌─────────────────────────────────────┐
│ Rank 0  │ Rank 1  │ Rank 2  │ Rank 3 │
│ (master)│ (worker)│ (worker)│ (worker)│
└─────────────────────────────────────┘
```

## 3. Какими вызовами должна начинаться и завершаться MPI программа?

### Начало (инициализация):
```c
// C
int MPI_Init(int *argc, char ***argv);
// или для thread-safe
int MPI_Init_thread(int *argc, char ***argv, int required, int *provided);

# Python (mpi4py)
MPI.Init()  # или просто import mpi4py.MPI (авто-инициализация)
```

**MPI_Init** должна вызываться **раньше любых других MPI функций**. Она:
- Инициализирует MPI среду
- Создаёт MPI_COMM_WORLD
- Определяет ранг и размер для каждого процесса
- Парсит командную строку (удаляет MPI-специфичные аргументы)

### Завершение (финализация):
```c
// C
int MPI_Finalize(void);

# Python
MPI.Finalize()
```

**MPI_Finalize** должна вызываться **после всех MPI операций**. Она:
- Завершает MPI среду
- Освобождает ресурсы
- Синхронизирует все процессы (неявный барьер)
- После неё нельзя вызывать MPI функции (кроме `MPI_Initialized` / `MPI_Finalized`)

### Правила:
1. `MPI_Init` — первой MPI функцией в программе
2. `MPI_Finalize` — последней MPI функцией
3. Каждый процесс должен вызвать обе функции
4. Между ними — вся MPI логика
5. Нельзя вызывать `MPI_Init` дважды без `MPI_Finalize`

### Пример структуры (C):
```c
int main(int argc, char** argv) {
    MPI_Init(&argc, &argv);           // 1. Начало
    
    int rank, size;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);
    
    // ... вся MPI работа ...
    
    MPI_Finalize();                    // 2. Конец
    return 0;
}
```

### Пример структуры (Python/mpi4py):
```python
from mpi4py import MPI

comm = MPI.COMM_WORLD  # Инициализация происходит при импорте
rank = comm.Get_rank()
size = comm.Get_size()

# ... вся MPI работа ...

MPI.Finalize()  # Явная финализация (опционально, происходит при выходе)
```

## 4. Объяснить преимущество асинхронных (неблокирующих) операций

### Суть различия:

| Блокирующие (Blocking) | Неблокирующие (Non-blocking) |
|------------------------|-------------------------------|
| `MPI_Send` / `MPI_Recv` | `MPI_Isend` / `MPI_Irecv` |
| `MPI_Bcast` | `MPI_Ibcast` (MPI-3) |
| `MPI_Scatter` | `MPI_Iscatter` (MPI-3) |
| `MPI_Gather` | `MPI_Igatherv` (MPI-3) |
| Ждут завершения операции | Возвращают управление сразу |
| Возвращают `MPI_Request` | Требуют `MPI_Wait` / `MPI_Test` / `MPI_Waitall` |

### Главное преимущество: **Перекрытие коммуникации и вычислений (Overlap)**

#### Блокирующий режим (последовательно):
```
Process A:  [SEND DATA]----->[WAIT]----->[COMPUTE]----->[SEND RESULT]----->[WAIT]
Process B:              [RECV DATA]----->[WAIT]----->[COMPUTE]----->[SEND RESULT]...
Time ─────────────────────────────────────────────────────────────────────────>
```
Процесс **простаивает** во время передачи данных.

#### Неблокирующий режим (параллельно):
```
Process A:  [ISEND]----->[COMPUTE OVERLAP]----->[WAITALL]----->[ISEND RESULT]...
Process B:      [IRECV]----->[COMPUTE OVERLAP]----->[WAITALL]...
Time ─────────────────────────────────────────────────────────────────────────>
```
Пока сеть передаёт данные, CPU **одновременно вычисляет**.

### Аналогия с CUDA Streams:
```
CUDA:  cudaMemcpyAsync (H2D) + Kernel Execution + cudaMemcpyAsync (D2H)
        │                    │                    │
        ▼                    ▼                    ▼
MPI:   MPI_Isend/Recv  +  Local Compute  +  MPI_Waitall
       (Data transfer)    (Overlapped)       (Sync)
```

### Конкретные выгоды:

1. **Скрытие задержки сети (Latency hiding)**
   - Время передачи = latency + size/bandwidth
   - Вычисления во время latency полностью скрывают её

2. **Пайплайнинг (Pipelining)**
   - Для итеративных алгоритмов: начинаем передачу итерации N+1, пока считаем N
   - Аналогично CUDA Streams: `stream 1: copy → compute → copy`, `stream 2: copy → compute`

3. **Лучшая утилизация ресурсов**
   - CPU не простаивает в ожидании сети
   - Сетевая карта не простаивает в ожидании CPU

4. **Масштабируемость**
   - На больших кластерах latency становится bottleneck
   - Non-blocking критичен для производительности

### Пример из нашей ЛР7 (умножение матриц):
```python
# Non-blocking версия
req_bcast = comm.Ibcast(B, root=0)      # Начинаем передачу B
req_scatter = comm.Iscatter(A, ...)     # Начинаем передачу строк A

# ЗДЕСЬ МЫ МОГЛИ БЫ НАЧАТЬ ВЫЧИСЛЕНИЯ, ЕСЛИ БЫ ДАННЫЕ УЖЕ БЫЛИ ЧАСТИЧНО ДОСТУПНЫ
# Но для матричного умножения нужны И A_local И B целиком

MPI.Request.Waitall([req_bcast, req_scatter])  # Ждём оба

C_local = A_local @ B  # Вычисление

req_gather = comm.Igatherv(C_local, ...) # Неблокирующая отправка результата
req_gather.Wait()
```

### Когда НЕ даёт прироста:
- Маленькие сообщения (latency доминирует, накладные расходы Request объектов)
- Когда вычислений очень мало по сравнению с коммуникацией
- Если сеть быстрее CPU (редко)
- При неправильном использовании (Wait сразу после Isend = blocking)

### Резюме:
> **Асинхронные операции позволяют перекрыть время передачи данных с полезными вычислениями, что аналогично концепции CUDA Streams (`cudaMemcpyAsync` + kernel). Главное преимущество — устранение простоев CPU в ожидании сети, что критично для высокопроизводительных MPI-приложений на больших кластерах.**
